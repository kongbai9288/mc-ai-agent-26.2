# MC 26.2 · AI 真正"会玩"Minecraft 的架构方案

## 一、先定位病根：为什么现在的 AI"玩不好"

不是模型不行，是**频率错配**。

| | 频率 | 特点 |
|---|---|---|
| LLM 决策 | 秒级（1 次 / 1–10 s） | 离散、语义、贵 |
| Minecraft 执行 | 20 tick/s | 连续、几何、便宜 |

现在大多数"AI 玩 MC"的方案，是让 LLM 直接下 tick 级的动作（按 W、转视角、点左键）。
结果就是：AI 每动一下都要来回一次网络请求，动作碎、延迟高、走不了十步就掉坑里。

**正确的做法是分层**——AI 只发"意图"，本地自动驾驶层负责 tick 级执行。

```
┌─────────────── L2 决策层（秒级，LLM） ───────────────┐
│  "去挖 20 个钻石" / "按投影把这一层建了" / "有怪，打"    │
└───────────────────────┬─────────────────────────────┘
                        │ 意图（一个指令管几百 tick）
┌───────────────────────▼─────────────────────────────┐
│  L1 桥接层（MCP / HTTP，127.0.0.1）                    │
│  把 Baritone / Printer / fakeplayer 封装成 tools      │
│  同时把世界状态、背包、实体、投影进度结构化回传           │
└───────────────────────┬─────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────┐
│  L0 执行层（tick 级，本地，完全不经过 AI）              │
│  Baritone    寻路/挖矿/建造/跟随/探索（# 命令）         │
│  Printer     按 Litematica 投影自动放方块              │
│  Carpet      /player xxx attack continuous 持久动作    │
└─────────────────────────────────────────────────────┘
```

你要的"**对某些操作不使用 API，可以持久操作**"，正好就是 L0 层——这是整套方案的关键，也是能跑起来的前提。

## 二、L0 执行层：三台现成的发动机

### 1. Baritone（男中音）——主力

一次命令，自主跑几百 tick，AI 完全不用插手。

| 命令 | 用途 |
|---|---|
| `#goto x y z` | 长途寻路（自己挖、自己搭桥、自己爬） |
| `#mine diamond_ore 20` | 挖到指定数量为止 |
| `#build <schematic>` | 按 schematic 建造 |
| `#farm [range]` | 自动收割 + 补种 |
| `#follow entity <type>` | 跟实体 |
| `#explore` | 自动探索未见区块 |
| `#stop` | 随时中断 |

26.2 可用版本：
- `dysnasia/baritone-26.2`（Mojmap，Fabric / Forge / NeoForge 三端，独立 jar）
- Meteor Client 的 `Baritone [26.2]` fork

**注意**：Baritone 是**客户端 mod**。服务端装不了。

### 2. Litematica + Printer（投影 + 打印机）

- 版本：`Litematica Printer 26.2-3.2.2`（2026-06-17 发布）
- 依赖：Fabric API + **MaLiLib** + **Litematica**（后两个不在 Modrinth，走 CurseForge / GitHub）
- 纯客户端，服务端不需要装
- 开关：默认 `Caps Lock`
- 已经自带"区域内缺失材料显示"、"工作进度条"——这两个直接就能喂给 AI 做决策

### 3. Carpet fakeplayer——服务端持久动作

Carpet 26.2 的 `/player` 全能力，桥接层要全部包成 tool：

```
/player <name> spawn [at<x y z>] [facing] [in <dim>] [in <gamemode>]
/player <name> kill | shadow
/player <name> <动作> [once|continuous|interval <n>]
   动作: use  attack  jump  drop  dropStack  swapHands
/player <name> move [forward|backward|left|right]
/player <name> look [north|south|east|west|up|down|at <x y z>]
/player <name> turn [left|right|back|<yaw> <pitch>]
/player <name> [sneak|unsneak|sprint|unsprint]
/player <name> hotbar <slot>
/player <name> [mount|dismount] [anything]
/player <name> stop
```

`continuous` 就是你要的"持久操作"——一个指令挂在那儿一直执行，AI 不用轮询。

## 三、L1 桥接层：三条现成路，选一条

| 方案 | 协议 | 覆盖 | 26.2 | 备注 |
|---|---|---|---|---|
| **MCPFabric**（denfry，MIT） | MCP over HTTP，bearer token，127.0.0.1 | 50+ tools：移动/挖掘/建造/战斗/背包/截图/事件/服务器运维 | ✅ 1.21.1–26.2 | 客户端 + 服务端都支持，自带 A* 导航 |
| **Minecraft MCP Server Mod** | MCP，localhost:8080 | execute_commands / get_player_info / get_blocks_in_area / take_screenshot | ✅ 26.2 | 有安全校验与命令白名单 |
| **Baritone MCP Bridge v0.3.0** | 扩展 8766 端点 | `client_baritone_goto/mine/stop/status` + `client_player_*` + `client_skill_*` + `client_container_state` | ✅ 26.2 | **最贴近你的需求**，直接把 Baritone 变 tool |

**我的建议：以 Baritone MCP Bridge 为主骨架，用 MCPFabric 补齐感知侧。**
理由：Bridge 已经把"Baritone 命令"和"精确交互（选物品、放方块、点容器）"都做成了 tool，而且明确声明走正常客户端交互路径（不用 /give /tp /setblock），这正是"AI 正常玩"的定义。

## 四、NBT 解析：别把原始 NBT 丢给 LLM

你提的"下载对应的 nbt 然后解析发 ai"——思路对，但要加一层**摘要**，否则 context 直接爆。

`.litematic` / `.schematic` / `.schem` 本质都是 gzip 过的 NBT。处理流程：

```
schematic (NBT, gzip)
   ↓ python nbtlib 解析
   ↓ 提取 palette + block states
   ↓ 分层摘要
   ├─ ① 总览：尺寸 X×Y×Z、总体积、方块总数
   ├─ ② 材料清单：block_id → count（降序 Top N）
   ├─ ③ 分层切片：y=0..N 每层的方块直方图
   ├─ ④ 差异：与当前世界对比 → missing blocks（Printer 已内置）
   └─ ⑤ 结构特征：空腔、红石元件位置、刷怪点
   ↓
发给 LLM 的是 ①②③⑤，不是 10 万个方块的原始数据
```

**世界状态也一样**：不要 dump 整个 chunk，只发"以玩家为中心 32×32×16 的方块直方图 + 实体列表（类型/距离/血量）+ 背包摘要 + 当前 Baritone 进程状态"。

## 五、自动躲避 / 自动攻击：要自己写一小块

**躲避**：Baritone 自带避让相关设置，加上 `#invert`（反向 = 逃离）基本够用。

**攻击**：Baritone 官方定位里**明确不做战斗**（"It is not a kill-aura"）。所以这块得自己补，三条路：

| 方案 | 做法 | 评价 |
|---|---|---|
| A. 自定义 Baritone Process | 继承 `BaritoneProcess`，写 `AiCombatProcess`：选目标 → `look_at` → 攻击冷却循环 → 血量阈值触发 `flee` | **推荐**，最干净，天然是"持久操作" |
| B. Carpet fakeplayer | `/player bot attack continuous` | 服务端可用，但挑目标能力弱 |
| C. MCP 逐次调用 | `client_player_look_at` + `client_player_attack` | 能用，但回到"AI 每 tick 管一次"的老问题 |

推荐 A，配合一个安全策略模块：血量 < 阈值 → 自动中断当前进程 → 切逃跑 Goal → 恢复后再继续原任务。

## 六、26.2 开发的硬约束（踩一个就编不过）

Minecraft 从 **26.1 起发布未混淆版本**，这是十年来最大的一次断裂：

1. **不写 `mappings`**（写了报 `were not built for Minecraft version 26.2`）
2. 插件 id：`fabric-loom` → **`net.fabricmc.fabric-loom`**
3. `modImplementation` / `modCompileOnly` → **`implementation` / `compileOnly`**
4. `loom { noIntermediateMappings() }`
5. 产物用 **`jar`** 任务，不再有 `remapJar`；不要 `withSourcesJar()`
6. 类名一律用 **Mojang 官方名**：`ServerWorld`、`ItemStack`、`ResourceKey`、`Identifier`
   （例：Fabric API 里 `ItemGroupEvents` 已改名 `CreativeModeTabEvents`）
7. **JDK 25 + Gradle 9.7.0** 锁死，别乱配：
   - Gradle 9.1.0 → `No matching variant ... required 9.1.0`
   - Gradle 8.14.3 → `Unsupported class file major version 69`

不确定 API 签名时，用 `javap -cp <classpath> <类名>` 自查，别信旧教程。

## 七、落地路线（建议按 P0→P4 推进）

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **P0** | 单机跑通最小闭环：MC 26.2 + Fabric + Baritone + MCP Bridge | AI 说"去 100 64 100"，人真的走过去了 |
| **P1** | 感知闭环：世界状态 / 背包 / 实体结构化回传 | AI 能说出"我背包里有 12 个原木，附近有 3 只僵尸" |

| **P4** | 战斗 / 躲避 Process + 安全策略 | 血量低自动逃，怪清完自动继续原任务 |

## 八、几个必须先想清楚的风险

1. **客户端 vs 服务端**：Baritone / Litematica / Printer 都是**客户端 mod**；Carpet 是**服务端 mod**。
   单机（integrated server）两者能共存，但一旦上专用服务器，客户端那套只有装了 mod 的那个玩家能用。
2. **反作弊**：Baritone 和 Printer 在多数公共服务器属于违规。整套方案请在**自己的世界 / 自己的服务器**跑。
3. **AI 失控**：给 `execute_commands` 加白名单，禁止 `/op`、`/stop`、世界删除类命令。MCPFabric 默认带 capability gate，别关。
4. **延迟**：LLM 一次往返 1–10 s，中间世界会变。所有 tool 调用前必须**重新读一次状态**，不能依赖缓存。
